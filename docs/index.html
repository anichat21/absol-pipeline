Absol

Workflow & skills

A project workflow for Claude Code — ideas go in as ledger items, work comes out as verified, archived runs. Items grow in place (shape → map → plan); the execute gate auto-fills what's missing; runs execute unattended, AFK and scheduled included.

Workflow

/absol is the only front door. It opens a session, recovers crashed or paused runs (one rule: a stale run.md gets finalized as crashed), prints a banner derived live from the ledger, then routes each turn — note-taker (capture), scratchpad (interactive), or a run (the default for action requests). Every unit of work is an item in the ledger that grows in place: a shape: block (your decisions), a map: block (codebase research), a plan: block (tasks). Saying "run BUG-014" pushes the item at the execute gate, which fills whatever's missing on the way through — only shaping can need you, so AFK and scheduled runs skip ambiguous unshaped items and log the blocking question instead of guessing.

Reading the diagram

Solid arrows are control flow; dashed arrows are data. Runs are bracketed by git commits (a pre-run snapshot anchor and a post-run fold; absol never pushes). Failed tasks re-aim instead of patching — retry 1 asks "is this the right way?", retry 2 exhausts into a recorded smell: on the item. An AFK run ends its turn completely: open questions land on items as open:, owed human checks become VERIFY items, and the next session's banner surfaces all of it.

Bookkeeping

One principle: store only what can't be recomputed — human decisions and outcomes; derive the rest. No status flags: an item is "planned" because a plan block exists on it; a run is "live" because .absol/run.md exists (its mtime is the heartbeat); history is an append-only archive/YYYY-MM.md. Done items are deleted at finalize — the archive block is their record. Every write is tool-owned; the human's manual surface is decisions only.

Skills & agents

Each component has one job. skill are invoked through /absol or directly; agent are spawned with their task inline in the prompt and only ever append events; internal run only as part of a flow. Agents inherit the session model — nothing is pinned. Schemas live once, in absol/references/schemas.md.

ComponentTypeRole
absol skill Front door. Opens a session, one-rule recovery, derived banner (owed smoke, open questions, smells, primed items), routes each turn. Schedules headless AFK runs via cron.
note-taker skill Captures thoughts as items — bug → bugs.md, debt → tech-debt.md, everything else → inbox.md — and transcribes decisive statements about existing items into their shape: blocks.
absol-shaper skill Settles intent, one question at a time, under a strict no-filler contract (ask only if the answer changes the plan and two options are genuinely defensible). Every shape names the refuse-boundary — what gets rejected, not recovered.
absol-research skill Read-only fan-out that maps each item's blast radius (entry points, consumers, sync hazards) into a dated map: block. Scales itself; trivial items get a two-line map.
absol-planner agent Designs the build as a plan: block of vertical-slice tasks. Gates: falsify the diagnosis first (bugs), reality-contact at task 1–2, simplest-that-clears-the-bar, honour the refuse-boundary. In retry mode it re-aims — mechanical slip vs wrong approach — and never patches a patch.
absol-orchestrate internal Run engine: execute gate → pre-run commit → serial execution → review → close. Passes each agent its task inline; in AFK mode nothing ever blocks on a question.
absol-executor agent One task per invocation. Climbs the ladder before writing (skip → reuse → stdlib → dependency → minimum that works); TDD for features and bigger bugs, direct edit for tweaks. Verifies honestly per oracle — unit suite, runtime probe, or owed-to-human; never claims pass on an unexercised path.
absol-reviewer agent Reviews flagged or failed tasks against acceptance criteria. Fix-required re-executes in-run; overbuild is a finding (hands back a delete-list).
absol-finalizer agent Closes a run: appends the outcome block to the monthly archive, folds results into the ledger (deletes done items, annotates partials with prior:/smell:, appends VERIFY items), snapshots state.md, post-run commit, deletes run.md.
absol-scratchpad skill Interactive mode on the same run/event model — build, fix, explore, or discuss live; can dispatch a dynamic workflow for big interactive builds. Same finalizer closes it.
absol-architect skill Interactive deepening pass (deletion test). Accepted candidates land as shaped ARCH items ready for the gate; rejections with durable reasons become ADRs. Sole ADR author.
absol-megareview skill Unattended deep sweep — bugs, logic flaws, smells/overbuild, dead code, structure, docs drift — with adversarial verification of every finding. Writes a report to .absol/reviews/ plus one ledger item pointing at it.
absol-explain skill One-minute plain-language orientation to all of the above.
absol-feedback skill Logs a problem with absol itself — from any project, mid-anything — as a dated note in the absol repo's feedback folder.
absol-newproject skill Scaffolds the .absol/ layout (ledger, CONTEXT.md, adr/, archive/, reviews/), .gitignore, git init. Skeleton only.
absol-migrate skill Upgrades a project to the current schema (currently: v1 notes/plan.md → v2 items). Reads first, applies on confirmation; git is the revert path.
absol-docs skill Manages the hosted documentation hub (this page lives here). Scaffolds, registers, and themes project docs served by homer.
