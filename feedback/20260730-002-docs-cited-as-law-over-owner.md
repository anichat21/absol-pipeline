# Sessions cite project docs as binding against the owner's live statements

- date: 2026-07-30 · project: arctic-tern · run: n/a
- component: front door / doctrine

## What happened

During the 0.2.0 feedback round the owner had to spell it out: "if something in the
documentation doesn't align, what I am telling you now stands as what I want, not the docs.
It's my project, not the docs' project. Weird habit you have constantly bringing up the docs
like it's some sort of law of the land that I must respect — I wrote those. For you, not me."
Sessions keep surfacing doc text (CLAUDE.md rules, conventions) as a counterweight when the
owner states intent that contradicts it, instead of treating the statement as the new truth
and the doc as stale.

## Expected

Owner's live statement supersedes any doc, immediately. The doc is what's wrong; the correct
move is conform-the-doc (or queue the rewrite), never quote-the-doc-back. Docs are written for
the agents, not as constraints on the owner. Candidate doctrine line: "docs bind agents, not
the owner — a live owner statement outranks any doc, and the doc gets rewritten to match."
